# 送信確認と通信切断・復旧の検証

対象はFlutter Android版0.12.0／33。実サービスの到着確認は[実送信確認](FLUTTER_LIVE_DELIVERY.md)、資格情報なしの障害試験は本書で扱う。実サービスの成功と模擬APIの成功を混同しない。

## 実装

- preview版に「Discord・Telegramの送信確認」画面を追加。有効な送り先、接頭語、確認あり／なしを表示し、明示操作で合成音声を1件受信する。通常の認識・保存・送信キューを使用する。未登録、リング自動受信中、認識中、未完了の送信がある場合は開始できない。production版にはこのメニューを出さない。
- 送信一覧にオフラインの案内を追加。OSがインターネット接続を検証できない場合に表示する。接続前の送信待ちは復旧を待ち、結果不明は自動再送しない。
- 通常の送信Workerは従来どおりWorkManagerのCONNECTED制約を使う。模擬APIの試験時だけ従来はこの制約を外していたが、previewDebugの専用ハーネスで制約を有効化する試験モードを追加した。Dartやproductionから有効化する入口はない。

## 再現手順

個人データのない専用API36エミュレーター5558を使う。previewDebugをビルド後、リポジトリ直下で実行する。

```sh
python3 scripts/test-android-delivery.py --device emulator-5558 \
  --reset-test-data --network-recovery-check
```

このコマンドは指定した試験アプリのデータを初期化し、専用エミュレーターの機内モード・Wi-Fiを切り替える。実送信確認用5556へ実行しない。終了時は機内モードを解除してWi-Fiをオンに戻す。ADB経由でホストの模擬HTTP APIへ接続し、実際のDiscord／Telegram APIへの投稿は行わない。

`--network-recovery-check`はネットワーク接続の検証ができるローカルAVD向け。従来のネットワークを切ったCIでは付けず、応答切断・プロセス終了・接続前失敗からの復旧などを実行する。

| 状況 | 確認する動作 |
|---|---|
| 機内モード・Wi-Fi／データともオフ | 2送り先のジョブが送信待ち・試行0回で残り、模擬サーバーへPOSTしない |
| オフライン中にプロセスを終了・再開 | 同じ未送信ジョブを保持する |
| 接続を復旧 | 両先に1件ずつ送信し、それぞれ試行1回・受領IDありになる |
| 送信済みの状態でプロセスを再開 | 追加のPOSTをしない |
| TCP接続前に失敗 | 再試行待ちにし、接続先の復旧・プロセス再開後、待機期限を守って1件を送信する |
| サーバーがPOST受領後、応答を切断 | 結果不明にし、再開後も自動POSTを追加しない |
| 応答待ち中にプロセスを終了 | 結果不明へ復旧し、承認なしでは再送しない |
| 429 | サービスの待機時間を守り、再試行回数の上限を適用する |
| 結果不明を手動再送 | 重複の可能性を確認する操作を必要とする |
| 送信中に録音を削除 | 送信結果で録音・ジョブが復活しない |

通常の試験は最初の合成音声について実Whisper認識を行う。通信制約の試験には固定の合成認識結果を使い、ASR性能を測定しない。サーバーへのPOST数、状態、試行回数で判定し、実サービスの到着や通知の代用にはしない。

結果不明では、外部サービスが受け取ったかを常に判定できるわけではない。重複を完全に防ぐ保証は追加しない。投稿先の確認後に手動対応する方針を維持する。

結果は `work/android-delivery-tests/evidence.json`。公開用の確定結果は `FLUTTER_DELIVERY_RECOVERY_EVIDENCE.json` に記録する。本文・資格情報・宛先IDは含めない。

## 2026-10-22の結果

API36 ARM64の専用AVDで上記の模擬API試験が成功した。初回の実Whisper認識、確認あり・複数送り先、接頭語・メンション制御、送り先オフと資格情報更新、結果不明と手動再送、429、グループ移行、送信中の削除、リダイレクト拒否、機内モードとプロセス再開、通信復旧後の非重複を確認した。

準備時にはAVD5556を0.12.0／33へ更新し、送り先0件を確認した。その後、利用者が2送り先を登録し、0.12.1／34で実API投稿と、利用者による両サービスへの各2件の到着確認まで成功した。接頭語・メンションは利用者の指定で追加試験を行わない。最新の確認範囲は[実送信結果](FLUTTER_LIVE_DELIVERY_EVIDENCE.json)を参照。
