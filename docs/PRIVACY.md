# データとプライバシー

## 保存と通信

録音・文字起こし・設定・ジョブはiPhoneのアプリ領域に保存します。日本語の文字起こしはAppleのオンデバイスSpeechAnalyzerを使用し、認識用モデルの準備にはダウンロードが必要な場合があります。独自の文字起こしサーバーはありません。

送り先を有効にすると、接頭語を含む文章をDiscord／Telegramへ送ります。音声は投稿に添付しません。送り先の登録確認時にも各サービスのAPIへ通信します。Telegramの受信メッセージ・候補は取得しません。第三者サービス側の保存・取り扱いは各サービスの規約・設定によります。

| 種類 | 保存先・保護 |
| --- | --- |
| WAV・録音情報 | Application Support / ReceivedRecordings |
| 文字起こし | Application Support / Transcripts |
| 自動処理状態 | 自動処理キューのJSON（登録リング・保存済み範囲など） |
| 送り先・本文・送信状態 | Application Support / Delivery |
| 削除履歴 | Application Support / History |
| トークン・Webhook URL | Keychain、AfterFirstUnlockThisDeviceOnly |
| 比較用音声・圧縮入力 | 詳細受信診断を使った場合のReceiverComparisons |

主要保存ディレクトリはOSバックアップ対象から除外し、保護クラスは初回ロック解除後にアクセスできる設定です。再起動後の初回解除前には処理できません。iCloud同期は実装していません。

資格情報は通常Keychainに保存しますが、URLSessionへ登録済みのリクエストにはURL／認証情報が含まれ、OS側に保持されます。資格情報を更新しても登録済み要求が自動で置換されるとは限りません。

Telegramのグループ名・数値ID・種類は登録時に取得し、送信設定として保存します。開始用リンクの生成や受信メッセージの取得は行いません。

## 削除・書き出し

ホームでの削除はその録音のWAV・録音情報・文章・送信ジョブを削除します。削除済みIDと受信位置などの制御情報は再取得防止のため残ります。標準補正の書き出し先、外部サービスへの投稿、共有先のコピーは別に管理してください。

詳細な受信診断で生成した比較用音声・圧縮入力は通常履歴とは別管理で、ホームの削除対象には含まれません。診断共有には音声が含まれ得ます。アプリを削除するとアプリ領域は消えますが、Keychain資格情報も必ず消えるとは扱いません。資格情報を不要にする場合は送り先設定を削除し、必要に応じサービス側で失効させてください。

## ログと報告

イベント診断は状態・時刻・数値メタデータ・エラーコードが中心です。文章・音声・トークンを通常ログへ出さない方針です。共有する前に内容を確認し、公開Issueへ実際の録音・文字起こし・Webhook URL・Botトークンを添付しないでください。ライブラリ／OSのログにも環境情報が含まれる可能性があります。


## 0.9.3の設定画面と静的チェック

保存済みの資格情報は編集画面へ読み込まず、空欄で編集内容を保存するときにKeychainから取得します。0.9.6でTelegramの個別DM登録・開始リンク・候補取得を削除しました。

受信ブリッジに含まれる既知のURL文字列と通信API文字列を、実機版・シミュレーター版ごとに静的チェックします。通信を遮断する機能ではなく、実際の送信先・送信内容や未知の通信手法の不在を証明しません。必要に応じ実機のAppプライバシーレポートや通信観測で確認してください。


## 0.9.4の受信診断（L2）

BluetoothFailureの外部reasonは文字列化せず、固定値`bluetooth_failure`にします。例外は`none`・`invalid_argument`・`invalid_state`・`other`の有限な分類だけを使います。エラー領域もCBErrorDomain、CBATTErrorDomain、NSURLErrorDomain、NSCocoaErrorDomain以外は`other`です。外部の例外本文・クラス名・未知のdomain・ファームウェア文字列を診断メッセージへ展開しません。コレクション番号、サンプル数、固定イベント名、数値コードなどは引き続き端末内の復旧診断に使用します。

受信診断画面の2か所のNSLogはDebugのみで、XcodeのDebug構成にDEBUGを明示しました。Releaseでも端末内のチェックポイント・アプリ内の診断・ユーザーが共有するレポートは残ります。この変更はOSや外部ライブラリの全出力を遮断するものではありません。アプリ切替画面の保護（L3）は0.9.5で実装し、[実装と実機確認手順](L3_IMPLEMENTATION_PLAN.md)に記載しています。


## アプリ切替時の表示保護（0.9.5 / L3）

対象Sceneが非activeになる時点で、単色の不透明なウィンドウを同期的に表示します。アプリ名とロックアイコンだけを表示し、通常画面・設定等のシートを覆います。同じSceneがactiveになったときに解除します。通知センター、コントロールセンター、権限要求の間もアプリ本文が隠れる場合があります。覆いはkeyWindowにならず、タッチ・アクセシビリティ操作の対象になりません。

共有先やOS自身のプレビュー、既に共有した内容、アプリ使用中の通常のスクリーンショット／画面収録を遮断する機能ではありません。バックグラウンドの受信・文字起こし・送信処理は従来どおりです。2026-10-20に利用者の画像でApp Switcherの覆いと復帰後の操作を確認しました。権限・共有・保存の全条件を網羅した確認ではありません。[実機確認の範囲](REMAINING_VERIFICATION.md)を参照してください。


## Telegramのグループ制限（0.9.6）

登録時のAPI応答でgroup／supergroup以外を拒否し、保存・新規ルーティング・要求生成・再送にも制限を適用します。既存DM・チャンネルを読み込むと無効化し、未送信分を取り消します。送信開始済み分は結果不明として扱い、復旧時のOS転送は取消を要求しますが、既に相手へ届いた投稿を取り消す保証はありません。確定済み履歴と遅れて届いた成功応答は記録として保持します。

個別候補のなりすまし対策とその実機試験は機能削除により対象外となりました。受信ブリッジ等の通信観測は別の確認として残ります。
