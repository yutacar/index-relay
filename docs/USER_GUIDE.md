# 使い方

## 受信・文字起こし

公式アプリと同じリングを同時に取り合わないよう、公式アプリのBluetooth許可をオフにします。Index Relayの歯車 → リング・自動文字起こし → 最初にリングを選択から探索します。リングのボタンを押して起こし、対象を選びます。

自動処理をオンにして、最初の日本語モデルの準備はアプリを前面に置いて完了します。以後はリングのボタンを押している間に話すと、受信後の文字起こしがホームに増えます。接続・モデル・iOSの実行時間により表示は遅れることがあります。アプリをスワイプして強制終了した場合は開き直してください。

## 送り先と確認方法

歯車 → 送り先・送信方法 → 送り先を追加。複数登録でき、オンの送り先へ送ります。

「送信前に確認する」は初期値オンです。文字起こし後、歯車 → 送信一覧から本文を確認して送信します。オフにすると変更後の新しい文字起こしを自動送信します。過去の確認待ちをまとめて承認する変更ではありません。

接頭語が`メモ`なら`メモ 文字起こし本文`の形で送ります。区切りは半角スペース。すでに作成済みの送信待ちは設定変更で書き換えません。

### Discord

通常テキストチャンネルの「連携サービス → ウェブフック」で作成したURLを入力します。登録時は送り先照合だけを行います。

メンションは接頭語に`<@ユーザーID>`、ロールなら`<@&ロールID>`。`@表示名`だけではメンションになりません。接頭語で明示したIDだけを許可し、`@everyone`・`@here`は抑制します。Webhook投稿に反応しないBotや相手の通知設定による違いはあります。フォーラム・スレッド指定は対象外です。

### Telegramのグループ投稿

1. 公式の`@BotFather`でBotを用意し、投稿したいグループに追加する。
2. グループ側でBotによるメッセージ送信を許可する。
3. アプリへBotトークンとグループの数値ID（`-123…`や`-100…`）を入力する。公開スーパーグループは`@group_name`も指定できる。
4. 「送り先を確認して保存」を押す。`getMe`と`getChat`で送り先を照合し、`group`または`supergroup`の場合だけ登録する。登録時に投稿は行わない。
5. 最初は送信前確認をオンにし、テスト用の文字起こしを意図したグループに送れることを確認する。

グループIDはグループ名や個人のIDと異なります。表示名を空欄にすると取得したグループ名を設定名に使います。接頭語、複数の送り先、送信前確認の設定は従来どおり使用できます。トピックの指定は対象外です。

個別DM・チャンネル・Saved Messagesには投稿しません。開始リンクやチャット候補の取得はありません。Botの受信メッセージを取得するAPIを呼ばず、Webhookの設定も変更しません。

0.9.5以前のDM・チャンネル設定は更新後の最初の起動で停止表示になります。未送信分は取消、送信開始済み分は結果不明として履歴に残します。旧送り先を新しいグループに自動で振り替えることはありません。送信済みの履歴を保ち、必要なら送信一覧で結果を確認して終了し、旧設定を削除してください。OSへ既に登録された転送は取消が間に合わない場合があるため、旧送り先への到着は確認が必要です。

## 送信が止まったとき

| 状態 | 操作 |
| --- | --- |
| 確認待ち | 本文を確認して送信、または送信しないを選ぶ |
| 要対応 | 送り先・資格情報・本文の長さを確認する |
| 再試行待ち | 通信回復やレート制限の待機後に再開 |
| 結果不明 | Discord／Telegramで実際の到着を確認し、確認済みとして終了するか再送を選ぶ |

結果不明は自動再送しません。到着済みの文章を再送すると重複します。Discordは2000、Telegramは4096 UTF-16単位を保守的な上限として扱い、超過時は編集が必要です。

## 履歴・音声

ホームは新しい順で、時刻と送り先ごとの結果をまとめて表示します。歯車の表示・保存件数は初期値30件。件数を減らすと古い項目をその場で削除します。

編集で行のチェックを複数選び、一括削除できます。削除確認は出ず、復元はできません。ⓘから標準補正した音声を再生・WAV書き出しできます。送信済みのDiscord／Telegramの投稿はローカル削除で消えません。

## 診断

歯車 → 診断・ログでイベントを共有・クリアできます。詳細なBluetooth／受信診断は自動受信をオフにしてから使用します。比較データには音声が含まれるため、公開Issueへそのまま添付しないでください。


0.9.2では、明示的に本文を承認・再送すると自動再試行の回数を数え直します。APIの待機時間中はその期限を守ります。診断に表示する試行回数は、最後の手動承認・再送からの回数です。


## 送り先の資格情報の編集

送り先の編集画面には、保存済みWebhook URL・Botトークンを読み込みません。変更するときだけ入力し、空欄で保存すると現在の資格情報を保存処理の中で使います。表示名・接頭語だけの編集では再入力不要です。別の送り先への付け替えは行わず、新規追加してください。

## アプリ切替時の画面保護（0.9.5）

アプリを離れている間は、本文の代わりにIndex Relayとロックアイコンを表示します。戻ると元の画面が表示されます。設定や音声詳細を開いていても対象です。通知センターや権限ダイアログを開いた際にも一時的に本文を隠します。リングからの受信・文字起こしは継続します。

実機への更新後は[実機確認表](L3_IMPLEMENTATION_PLAN.md#実装後の実機確認表)に沿って、アプリ切替画面の表示と、共有・ファイル保存後の操作復帰を確認してください。

## Telegramグループが移行したとき

「グループが移行しました」と表示された場合は、古い送り先をオフにし、案内された新しいID（`-100…`）で送り先を追加して確認してください。送り先や保留中の投稿を自動で付け替えることはありません。古い投稿は送信一覧で確認して取消してください。新しい送り先を追加しても過去の文字起こしは自動送信されません。必要な本文は到着状況を確認してから手動で送ってください。
