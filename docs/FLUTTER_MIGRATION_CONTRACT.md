# Flutter移行時に維持する仕様（0.9.7を基準）

step 1・2の試作は別パッケージの`flutter_probe/`で行う。本番アプリの版、保存先、Bundle ID、Keychain、BGTask識別子、受信ブリッジのビルド設定を変更しない。

## 保存と処理担当

- `ReceivedRecording`のID、受信時刻、録音時刻の根拠、サンプルレート／数、collectionIndex、連続性、転送情報を保持する。
- 音声と録音メタデータの永続保存後に、AutomaticQueueの保存済み範囲とジョブを確定する。保存前に受信カーソルを進めない。
- 受信フロンティアの16bitロールオーバーと欠落区間を保持する。再接続・再起動を新規録音として重複登録しない。
- 認識ジョブのqueued／processing／done／needsAttention、失敗回数、再試行期限を保持する。認識の中断と送信結果不明を混同しない。
- iOSのJSONはSwiftのJSONEncoder／Decoderが現在の形式を維持する。Dartから日時やSetを再エンコードして既存ファイルへ上書きしない。形式変更は移行処理・バックアップ・失敗時復旧のテストを用意してから行う。
- 各OSの永続キューはネイティブ側が単独で書く。Flutterは型付きAPIで操作し、イベント受信が途切れたら保存状態を再取得する。

## 投稿

- 確認あり／なしは新しく発生するジョブへ反映する。既に確認待ちのジョブを設定変更で自動承認しない。
- 接頭語がある場合は「接頭語＋半角スペース＋文字起こし本文」。本文に含まれる任意の@文字列でDiscordの通知を許可しない。設定した接頭語の明示的なユーザー／ロールIDだけを許可する。
- Telegramはgroup／supergroupに限定。個別DM・チャンネル・受信候補取得は対象外。移行先IDを検出して案内し、自動付け替えはしない。
- 送り先ごとのスナップショット・試行UUID・回数・receipt・retryAfterを保持する。資格情報はスナップショットに含めず、送信時にKeychain／Keystoreで解決する。
- Discord wait=true、Telegram plain text、長文の要対応、429の待機を維持する。5xx／タイムアウトを一律に未送信と判断しない。
- sendingのOS転送を復元できなければunknownにし、自動再送しない。初期インストールの既存文章・送り先追加時の過去文章を勝手に投稿しない。

## UI・削除・保護

- 新しい順の本文・時刻・送り先状態、設定を歯車内へまとめる構成を維持する。
- 保存件数は初期値30、設定可能。複数選択・全選択の削除は確認ダイアログを出さない。音声詳細から標準補正再生・書き出し。
- ローカル履歴削除で外部投稿を消さない。削除と進行中ジョブの競合を扱い、古い非同期結果が削除した記録を復活させない。
- iOSのファイル保護・バックアップ除外・資格情報の画面非再読込を維持する。ログに個人の音声・本文・資格情報を出さない。
- Flutter化後もiOSのScene保護とAndroidの保護処理を別に接続する。Flutter画面だけでOSのsnapshot保護を保証しない。

## 検証

既存Swift 12スイート・506チェックを移行前の振る舞いの基準にする。Dartへ移すロジックは対応するケースを再実装し、ネイティブに残す処理は既存試験を継続する。Pythonの公開検査・Wrapper・ブリッジ検査とNative診断も維持する。Android依存と新しい認識エンジンの検査は別に追加する。

エミュレーターの合格範囲と、Index01実機・省電力・ロック中・メーカー別の未確認範囲を別記する。iOSの実機確認済みという過去の結果を、新しいFlutter UIやAndroidの実機保証へ読み替えない。
