# Flutter step 3：画面と模擬受信・実認識・保存

対象：Flutterプレビュー0.2.0 / build 2。既存iOS 0.9.7は変更しない。

## 実装

- ホーム：新しい順の文字起こし、時刻、待機／認識中／要対応／未連携。模擬受信と明示して実接続と区別。
- 歯車：表示・保存件数（初期30、1〜200）、送信前確認、送り先候補、模擬受信、SDK診断。
- 送り先候補：Discord／Telegramグループの表示名・IDのメモ・接頭語を端末内に保存。編集・削除。トークンやWebhookは受け付けず、API照合・実投稿はstep 6へ分離。候補登録で「連携済み」にしない。
- 編集：複数選択・全選択・選択解除・一括削除。左スワイプ削除。確認ダイアログなし。
- 音声詳細：標準補正での再生・停止、システムの保存先選択を経由したWAV書き出し。
- 模擬受信：既知の合成日本語WAVを1件の受信として保存し、実際のWhisperで認識して履歴を更新。毎回異なるイベントIDとし、同じ音声を独立した録音として追加できる。

## 永続化と競合

AndroidのSQLiteと音声ファイルをネイティブ側で管理し、Flutterはチャネル経由で操作する。ストアと推論を別ワーカーにし、長い認識の最中も削除・設定変更を受付できる。状態変更のイベントを受けてFlutterが保存状態を再取得する。

音声をファイルへ書いてsyncし、DBの同期設定FULLでメタデータ・待機ジョブを記録する。再起動時はprocessingをqueuedへ戻す。保存上限を適用し、登録されていない残存音声を掃除する。補正WAVも一時ファイルへの保存完了後に置換する。

認識完了時はID・試行ID・processing状態の一致する既存行だけをUPDATEし、INSERTしない。認識中に削除／上限整理された行が遅い結果で復活することを防ぐ。Flutterでも更新済みの状態を古い読込応答で上書きしない。

原音・補正音声・DBをnoBackupFilesDirに置き、アプリの自動バックアップを無効にする。本文・音声・資格情報をログへ出さない。候補に資格情報は保持しない。ユーザーが保存先を選んで書き出したWAVは、ローカル履歴の削除では削除しない。

## 検証範囲

標準補正は既存Swift AudioSignalのadaptive処理を16kHz入力に対して移植した。Swift実装で生成した640サンプルの境界値を含む正解データと、Androidの出力WAVをバイト単位で比較する。これは全入力レート・全録音に対する証明ではない。

専用Android API 36 ARM64 AVDで、ネット接続をオフにして検証する。WidgetテストはFakeBackendを使うが、Android統合テストの音声認識はJNI経由のWhisper実処理を使用する。

## 対象外

実Index01のBLE受信、Android Foreground Serviceやロック中の継続、実投稿・送り先API照合、資格情報のKeystore保存、本番データの移行は後続ステップ。iOS側の永続ストアと自動受信の接続はstep 4。今回の新しいホームの保存・再生・模擬受信はAndroidで検証し、既存iOS版の実機確認結果を流用しない。

[再現手順](../flutter_probe/README.md)。試験データとモデルはGit対象外、標準補正の合成正解JSONだけをソースとして保持する。

## 標準補正の比較データの再生成

リポジトリのルートで実行する。公開の合成境界値だけを使い、個人の音声は含めない。

```sh
mkdir -p work
xcrun swiftc ios/IndexRelay/PCM16WAV.swift ios/IndexRelay/AudioSignal.swift \
  tests/AudioSignal/generate_flutter_golden.swift -o work/flutter-audio-golden
work/flutter-audio-golden > flutter_probe/assets/audio-golden.json
```

- Flutter analyze：問題なし。Widget／Controller 11テスト成功。
- Android統合2テスト成功。標準補正のSwift正解との完全一致、UIからの模擬受信→実認識→保存、候補・設定保存、不正設定の拒否、音声再生、認識中の削除、保存上限による音声削除を確認。
- 既存のAndroid認識試作2テストも成功。iOSシミュレーターの既存Swiftバックエンド接続1テストも成功。iOSの新しい履歴保存を確認した結果ではない。
- 通常起動のアプリで模擬受信した後、プロセスをforce-stop。SQLiteにdoneの履歴が保存され、再起動後も同じ文章がホームに表示されることを確認。
- システム保存画面からDownloadsへWAVを保存。アプリ内の成功表示と、16kHz／mono／PCM16・114692フレームのファイルを確認。
- ネイティブの再生開始・停止の成功を確認。AVDは音声出力を無効にしているため、実際の聴感は確認していない。
- 既知の合成日本語文でも「録音」部分の誤認識は残る。認識精度の問題を文章の置換で隠さず、実結果を保存・表示する。
